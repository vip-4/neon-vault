玩法：四步开始一局

从打开页面到完成一次旋转，通常不到一分钟。所有操作都可以用鼠标、触屏或键盘完成。

    点击页面中的「开始游戏」，或滚轮进入试玩区后点击画面。初始余额为 1,000 虚拟信用点。

  2. 选择下注

    中奖金额自动加入余额并推进金库进度。达到 10,000 点触发通关；余额低于 10 点且无法下注时游戏结束，可重新开始。

// FAIRNESS & RNG

随机数、公平性与理论 RTP

SHORT ANSWER每次旋转的符号结果都在浏览器本地生成。现代浏览器优先使用 Web Crypto 的 crypto.getRandomValues() 并按拒绝采样消除取模偏差；不支持时回退到 Math.random()。没有服务端、账户或远程接口参与结果。按公开权重与赔率计算，理论 RTP 为 99.085%（约 99.1%）。

结果如何产生？

每局开始时，程序为 5 条卷轴各生成 3 个符号，共 15 个格子。每个符号从权重表中独立抽取，权重与上方赔率表一致。随后才播放旋转与停轮动画，因此动画只负责呈现结果，不会在落定瞬间改写结果。

符号选择使用拒绝采样：如果随机整数落在不能被权重总和整除的尾部区间，就丢弃并重新抽取，避免简单取模带来的微小偏差。此机制在浏览器本地执行，不发送任何数据。

RTP 与庄家优势

理论 RTP 为 99.085%，对应约 0.915% 的数学庄家优势。它表示在极大量旋转后，总返还金额占下注总额的期望比例，而不是“投入 100 点必定返还 99.085 点”。单次会话可能大幅高于或低于该值。

本地数据与隐私

游戏只使用 localStorage 保存历史最高分（键名 neon_vault_high_score_v1）。不使用 Cookie、不采集个人信息、不加载分析脚本，也没有运行时网络请求。清除浏览器站点数据即可删除本地记录。

// ACCESSIBILITY & TECH

设备支持、无障碍与技术说明

页面从 320px 宽的手机到桌面大屏均可使用，并提供鼠标、触屏、键盘与屏幕阅读器友好的替代控制。

无障碍设计

  • 语义化结构：页头、导航、主内容、章节、表格、页脚与跳转链接均有明确地标；全页只有一个 H1。
  • 真实控制栏：画布下方提供 HTML 按钮，可开始游戏、调整下注、打开赔率表与静音，不依赖 Canvas 命中区域。
  • 状态播报：旋转、中奖、余额不足、通关与游戏结束会写入 aria-live 状态区域，屏幕阅读器可自动朗读。
  • 键盘焦点：所有链接、按钮与画布都有可见焦点环；画布获得焦点后才启用游戏快捷键，避免劫持页面滚动。
  • 响应式与对比度：移动端按钮至少 42px 高，正文与背景保持高对比；页面尊重 prefers-reduced-motion，减少界面过渡。

技术架构

页面由单个 HTML 文件构成，CSS 与 JavaScript 内联，符号、背景、按钮和动画全部由 Canvas 2D 与 CSS 绘制。音效使用 Web Audio 实时合成，没有音频文件；图标为本地 SVG / PNG，不依赖 CDN。静态文件部署在 Cloudflare Pages，并通过 _headers 设置安全响应头与缓存策略。
